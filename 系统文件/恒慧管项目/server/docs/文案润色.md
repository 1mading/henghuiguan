# 文案润色（管理员工具）

侧栏「SQL脚本」下方入口，仅 `gm` / `admin`（且能力矩阵 `nav.textPolish` 开启）可用。用于把口语草稿润色为钉钉通知、对乙方沟通、内部催办或邮件正文。

## 配置方式（推荐：页面配置）

在 H5「文案润色」→ **接口配置** 中填写并保存：

| 项 | 说明 |
|----|------|
| Base URL | OpenAI 兼容网关，如 `https://api.deepseek.com/v1` |
| API Key | 密钥（保存后写入业务库 `llmSettings`，页面可回显） |
| 模型列表 / 默认模型 | 模型 ID，每行一个 |

服务端调用时：**页面保存的密钥与地址优先**；未在页面配置时回退 `.env`。

> MySQL 模式下配置落在 `app_meta.key = llmSettings`；JSON 模式下落在业务库根字段 `llmSettings`。

可选环境变量（兜底，非必须）：

| 变量 | 说明 |
|------|------|
| `LLM_BASE_URL` | 默认 `https://api.deepseek.com/v1` |
| `LLM_API_KEY` | 密钥（**勿提交 Git**） |
| `LLM_DEFAULT_MODEL` | 默认模型 ID |
| `LLM_MODELS` | 首次种子模型列表（逗号分隔） |
| `LLM_TIMEOUT_MS` | 请求超时，默认 `60000` |

> 密钥落在业务库时请确保 `server/data/` 不入库；勿把真实 Key 写进文档或 Git。

## 接口（JWT + 管理员）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/text-polish/options` | 含 `baseUrl`、`apiKey`、模型、场景、`templates` |
| PUT | `/api/text-polish/models` | Body: `{ models, defaultModel?, baseUrl?, apiKey? }` |
| POST | `/api/text-polish` | Body: `{ draft, scene?, model?, extra? }` → `{ polished, model, scene }` |
| POST | `/api/text-polish/templates` | Body: `{ name?, content, scene? }` 将正文存为模版 |
| DELETE | `/api/text-polish/templates/:id` | 删除模版 |
| POST | `/api/text-polish/send-chat` | Body: `{ cid, content }` → 以当前用户身份发到所选群/单聊 |
| GET | `/api/dingtalk/jsapi-config?url=` | 当前页 URL（不含 `#`）→ `dd.config` 签名包 |

场景 `scene`：`dingtalk` | `vendor` | `urge` | `email` | `custom`。

模版保存在业务库 `llmSettings.templates`（最多 50 条）。页面「存为模版 / 模版库」可选用到结果区或草稿。

## 发送到群聊

润色结果区点击 **发送到群聊**（需在钉钉客户端内打开恒慧管）：

1. 前端先向后端取 JSAPI 签名并 `dd.config`，再调用 `chooseChat` / `pickConversation` 让用户选群（仅企业内部群，且须为当前用户所在群）。若报 `API not authed`，检查钉钉应用是否已发布并开通选会话相关权限。
2. 取得一次性 `cid` 后，调用 `POST /api/text-polish/send-chat`。
3. 服务端以当前登录用户的 `dingTalkUserId` 为发送者，调用钉钉 `message/send_to_conversation` 发送纯文本。

要求：当前账号已绑定钉钉 userid；钉钉应用已配置 AppKey / Secret / AgentId。浏览器直接访问时可用「复制」后手动粘贴。

上游润色调用：`POST {baseUrl}/chat/completions`。
