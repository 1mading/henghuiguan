# 恒慧管 · 第三方写入接口文档

第三方系统通过 **API Key** 调用本接口，向恒慧管写入项目、任务、评论、依赖、人员等数据，无需用户 JWT 登录。

配套只读查询见：[workbuddy.md](./workbuddy.md)

---

## 1. 前置条件

1. 在 `server/.env` 配置 `API_KEY`（可用 `npm run rotate-secrets` 生成）
2. 配置 `PUBLIC_BASE_URL` 为第三方可访问地址
3. 重启后端服务

未配置 `API_KEY` 时，全部写入接口返回 `503`。

---

## 2. 基础约定

### 2.1 Base URL

```
{PUBLIC_BASE_URL}/api
```

本地默认：`http://localhost:3000/api`

### 2.2 鉴权

| 方式 | 说明 |
|------|------|
| Header `X-Api-Key: <密钥>` | **推荐** |
| Query `?key=<密钥>` | 备选 |

密钥匹配环境变量 `API_KEY`。

### 2.3 统一响应

成功：

```json
{
  "code": 200,
  "message": "ok",
  "data": { }
}
```

失败：

```json
{
  "code": 400,
  "message": "错误原因",
  "data": null
}
```

| HTTP / code | 含义 |
|-------------|------|
| 200 | 成功 |
| 400 | 参数错误 |
| 401 | 密钥错误或缺失 |
| 404 | 资源不存在 |
| 409 | 冲突（如 ID 已存在、依赖重复） |
| 500 | 服务端写入失败 |
| 503 | 未配置 `API_KEY` |

### 2.4 Content-Type

请求体使用 JSON：

```
Content-Type: application/json
```

### 2.5 人员字段解析

凡涉及人员的字段（`manager` / `assignee` / `creator` / `author` / `teamMembers` 等）支持：

- 姓名（如 `王元斌`）
- 系统用户 `id`
- 钉钉 `userid` / `dingTalkUserId`
- 对象：`{ "name": "王元斌" }` 或 `{ "dingTalkUserId": "669701617" }`

服务端会尽量解析为系统内姓名；解析不到则原样写入字符串。

### 2.6 日期格式

日期字段接受：

- `YYYY-MM-DD`（推荐）
- `YYYY/M/D`
- 可被 `Date.parse` 解析的字符串

统一规范为 `YYYY-MM-DD`。

### 2.7 实时同步

写入成功后会广播 SSE 变更事件，已打开恒慧管前端的客户端会 soft-pull 刷新。

**注意：**

1. 当前生产库若配置 `DB_DRIVER=mysql`，数据落在 MySQL，不要去对 `server/data/*.json` 核对。
2. 若有人正在打开前端并触发 `PUT /api/data/sync`，旧客户端快照可能盖掉刚写入的字段；写入后可用 `GET /api/data/bootstrap`（管理员 JWT）或再次 `GET /external/...` 核对落库结果。
3. 前端已打开页面时，变更需字段指纹变化才会重绘；计划书字段（`objective`/`endDate`/`name` 等）现已纳入指纹。仍异常时请强制刷新（Ctrl+F5）。

---

### 2.8 与项目详情页签字段对照

| 页面页签 | 主要接口 | 关键字段 |
|----------|----------|----------|
| 计划与推进 | `PATCH /external/projects/:id`；阶段同步 `POST /external/projects/:id/sync-phase` | 计划书：`name`、`manager`、`dept`、`teamMembers`、`objective`、`value`、`scope`、`outOfScope`、`endDate`、`changeReason`；推进：`currentPhase`、`nextPlan`、`blocker` |
| 阶段执行 / 登记册 | `GET/PUT .../registers`；`PATCH .../document-slots`；或 `PATCH /external/projects/:id` 直写数组 | `stakeholders`、`commPlans`、`qualityChecks`、`risks`、`budgetLines`；文档槽 `phaseKey`/`slotKey` |
| 项目执行 | `POST/PATCH /external/tasks`；验收记录文件走 `POST /api/files/upload`（`uploadPurpose=evidence`），钉钉文档/闪记走登录态 `POST /api/files/link-dingtalk-doc`（`nodeId`+`workspaceId` 或 `url`，`linkPurpose=evidence`） | 里程碑：`deliverables`、`acceptanceCriteria`、`outOfScope`、`roleA`/`roleR`/`roleC`/`roleV`；通用：`feedback`、`leftover`；验收记录为附件 `purpose=evidence` 或钉钉文档 `source=dingtalk_wiki` |
| 项目交接 | `POST /external/projects/:id/handover` | `to` / `toName`、`note` |
| 问题闭环 | `GET/POST /external/issues`、`PATCH /external/issues/:id`、`POST .../issues/from-blocker` | `title`、`fact`/`cause`/`impact`/`solution`、`status` 等 |
| 项目变更列表 | `POST /external/change-logs` 或 `GET /external/history` | **必须**带 `projectId` 或 `project`（项目名/ID）或可关联的 `taskId`，否则详情页「项目变更」过滤不到 |

项目成员展示读的是 `teamMembers`（会自动去掉与 `manager` 同名的人）。只写 `manager`、不写 `teamMembers` 时，表头可能显示「暂无成员」或仅负责人。

### 4.1 连通性

```http
GET /api/external/health
X-Api-Key: <密钥>
```

响应 `data` 示例：

```json
{
  "service": "henghuiguan-external-write",
  "time": "2026-08-21T07:00:00.000Z"
}
```

### 4.2 接口目录

```http
GET /api/external/catalog
X-Api-Key: <密钥>
```

返回鉴权说明与 endpoints 列表，便于 Agent / 脚本动态发现。

### 4.3 项目模板

```http
GET /api/external/project-templates
```

返回 `{ "templates": [ ... ] }`（公开字段）。

```http
POST /api/external/project-templates/from-project/:id
Content-Type: application/json
```

从已有项目另存模板。Body 可选：`name`、`desc`、`id`。  
**作用域 Key 不可调用**（返回 403）；须用全局 `API_KEY`。

## 5. 项目

### 5.1 创建项目

```http
POST /api/external/projects
X-Api-Key: <密钥>
Content-Type: application/json
```

> **作用域 Key**：允许创建（须绑定人具备「新建项目」权限）；负责人/创建人默认取绑定人姓名。  
> **删除项目**仍禁止作用域 Key。

#### 请求体

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `name` | string | ✅ | 项目名称（亦接受 `title`） |
| `id` | string | | 自定义 ID；不传则自动生成 `PRJ-...` |
| `desc` | string | | 描述（亦接受 `description`） |
| `dept` | string | | 归属部门 |
| `manager` | string/object | | 项目负责人，默认取 creator 或「外部系统」 |
| `teamMembers` | string[] | | 团队成员（自动排除负责人） |
| `status` | string | | `active` / `paused` / `done` / `archived`，默认 `active` |
| `startDate` | string | | 开始日期，默认今天 |
| `endDate` | string | | 结束日期（最终完成时间） |
| `archived` | boolean | | 是否归档 |
| `creator` | string | | 创建人 |
| `withTemplate` | boolean | | 是否生成标准阶段里程碑+门禁，**默认 true** |
| `stageTemplateId` | string | | 指定模板 ID；不传则可用默认 WMS 模板（与 `withTemplate` 配合） |
| `objective` | string | | 项目目标 |
| `value` | string | | 项目价值 |
| `scope` | string | | 范围（做什么） |
| `outOfScope` | string | | 不做范围 |
| `currentPhase` | string | | 当前阶段（项目推进状态，手动维护） |
| `nextPlan` | string | | 下一步计划 |
| `blocker` | string | | 当前卡点 |
| `planVerified` | boolean | | 计划台账是否已由陈璇校验 |
| `planVerifiedBy` | string | | 校验人 |
| `planVerifiedAt` | string | | 校验时间 |
| `documents` | array | | 项目文档列表（元素可含 `phaseKey`/`slotKey`） |
| `stakeholders` | array | | 干系人登记册 |
| `commPlans` | array | | 沟通计划 |
| `qualityChecks` | array | | 质量检查点 |
| `risks` | array | | 风险登记册 |
| `budgetLines` | array | | 预算明细（内部） |
| `externalMeta` | object | | 第三方自定义元数据（原样保存） |

#### 响应 `data`

```json
{
  "project": { "id": "PRJ-...", "name": "...", "...": "..." },
  "templateTaskCount": 13
}
```

`withTemplate: true`（默认）时会自动创建 6 个阶段里程碑及 M1~M7 门禁任务。

#### 示例

```bash
curl -X POST "$BASE/api/external/projects" \
  -H "X-Api-Key: $KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "NCC 升级项目",
    "manager": "王元斌",
    "dept": "信息中心",
    "withTemplate": true,
    "objective": "完成 NCC 升级上线",
    "value": "提升财务与供应链协同效率",
    "scope": "财务模块+供应链主流程",
    "outOfScope": "不包含生产 MES",
    "endDate": "2026-12-31",
    "currentPhase": "02-规划过程组",
    "nextPlan": "完成需求确认评审",
    "blocker": "等待业务方签字",
    "externalMeta": { "source": "erp", "bizId": "PRJ-10086" }
  }'
```

不生成模板：

```json
{ "name": "轻量项目", "manager": "王元斌", "withTemplate": false }
```

### 5.2 更新项目

```http

```

传入需修改的字段即可（部分更新）。支持字段同创建，另可传 `operator`（操作人，用于审计事件）。

响应：`{ "project": { ... } }`

更新计划书示例：

```bash
curl -X PATCH "$BASE/api/external/projects/PRJ-xxx" \

  -H "Content-Type: application/json" \
```

```bash
  -H "Content-Type: application/json" \
  -d '{
    "stakeholders": [
      { "name": "王元斌", "role": "甲方负责人", "dept": "项目管控部", "influence": "高", "freq": "每周" }

    ],
    "operator": "贾维斯"
  }'
```

### 5.2.0 项目登记册

#### 读取

```http
GET /api/external/projects/:id/registers
```

返回：`stakeholders` / `commPlans` / `qualityChecks` / `risks` / `budgetLines`，以及带 `phaseKey`/`slotKey` 的 `documents` 摘要。

#### 整表替换某一登记册

```http
PUT /api/external/projects/:id/registers/:registerKey
```

`registerKey` 取值：`stakeholders` | `commPlans` | `qualityChecks` | `risks` | `budgetLines`。

Body 传 `rows`（或 `items`，或与登记册同名数组）：

```bash
curl -X PUT "$BASE/api/external/projects/PRJ-xxx/registers/risks" \
  -H "X-Api-Key: $KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "rows": [
      { "desc": "接口字段未定", "level": "高", "prob": "中", "impact": "高", "action": "本周锁定", "owner": "黄艳", "status": "跟进中" }
    ],
    "operator": "贾维斯"
  }'
```

#### 标注文档槽

```http
PATCH /api/external/projects/:id/document-slots
```

```bash
curl -X PATCH "$BASE/api/external/projects/PRJ-xxx/document-slots" \
  -H "X-Api-Key: $KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "updates": [
      { "fileId": "FILE-xxx", "phaseKey": "M2", "slotKey": "blueprint" }
    ]
  }'
```

常用槽位：`charter`（章程）、`blueprint`（功能蓝图）、`vendor_proposal`（厂商方案）、`meeting_md`（会议纪要）、`accept_report` 等（与 WMS 阶段模板一致）。  
**同一 `phaseKey`+`slotKey` 可对应多个文档**（多次 PATCH 标注即可，不会互相覆盖）。

| 字段 | 类型 | 必填 | 说明 |

## 6. 任务

### 6.1 枚举值

**状态 `status`**

| 值 | 含义 |
|----|------|
| `todo` | 未开始（默认） |
| `doing` | 进行中 |
| `paused` | 已暂停 |
| `done` | 已完成 |
| `abolished` | 已废止 |
| `archived` | 已归档 |

**优先级 `priority`**

| 值 | 含义 |
|----|------|
| `urgent` | 紧急（亦接受「紧急」） |
| `important` | 重要（亦接受「重要」） |
| `normal` | 普通（默认） |

**类型 `type`**

| 值 | 含义 |
|----|------|
| `temp` | 临时事项（无 `projectId` 时默认） |
| `normal` | 普通项目任务（有 `projectId` 时默认） |

---

### 6.2 创建任务

```http
POST /api/external/tasks
```

> **作用域 Key**：  
> - 不传 `projectId`（或 `type=temp`）→ 临时事项，允许增删改（按绑定人任务权限）  
> - 传 `projectId` → 须对该项目有管理权

#### 请求体

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `title` | string | ✅ | 标题（亦接受 `name`） |
| `id` | string | | 自定义 ID；不传则 `T-...` |
| `desc` | string | | 说明 |
| `projectId` | string | | 所属项目；空则为临时事项 |
| `parentId` | string/null | | 父任务 / 所属里程碑 |
| `isMilestone` | boolean | | 是否阶段里程碑，默认 `false` |
| `milestoneSeq` | string | | 里程碑序号，如 `M1`（仅里程碑） |
| `roleA` / `roleR` / `roleC` / `roleV` | string | | A唯一交付人 / R直接执行人 / C协作人 / V业务验收人 |
| `deliverables` | string | | 交付物 |
| `acceptanceCriteria` | string | | 验收标准 |
| `outOfScope` | string | | 本里程碑不做范围（与项目计划书 `outOfScope` 不同） |
| `completionEvidence` | string | | 已不再在页面填写；历史文字可保留 |

## 13. 批量写入

```http
POST /api/external/batch
```

一次完成多实体 upsert 与显式删除。有 `id` 且已存在则更新，否则创建。

#### 请求体

```json
{
  "withTemplate": false,
  "projects": [
    { "id": "PRJ-EXT-1", "name": "批量项目", "manager": "王元斌", "currentPhase": "01-启动过程组", "nextPlan": "联调接口", "blocker": "" }
  ],
  "tasks": [
    { "id": "T-EXT-1", "title": "任务A", "projectId": "PRJ-EXT-1", "assignee": "王元斌" },
    { "id": "T-EXT-2", "title": "任务B", "projectId": "PRJ-EXT-1", "assignee": "王元斌" }
  ],
  "taskDependencies": [
    { "predecessorTaskId": "T-EXT-1", "successorTaskId": "T-EXT-2" }
  ],
  "users": [
    { "name": "外部同步员", "dingTalkUserId": "123456", "dept": "信息中心" }
  ],
  "removedProjectIds": [],
  "removedTaskIds": [],
  "removedDependencyIds": []
}
```

| 字段 | 说明 |
|------|------|
| `withTemplate` | 仅对**新建**项目生效；默认 false（批量场景避免刷大量模板任务） |
| `projects` | 项目 upsert 列表 |
| `tasks` | 任务 upsert 列表 |
| `taskDependencies` | 依赖 upsert 列表 |
| `users` | 人员 upsert 列表 |
| `removedProjectIds` | 显式删除项目（级联任务） |
| `removedTaskIds` | 显式删除任务 |
| `removedDependencyIds` | 显式删除依赖 |

#### 响应 `data`

```json
{
  "projectsUpserted": 1,
  "tasksUpserted": 2,
  "dependenciesUpserted": 1,
  "usersUpserted": 1,
  "projectsRemoved": 0,
  "tasksRemoved": 0,
  "dependenciesRemoved": 0
}
```

处理顺序：项目 → 任务 → 依赖 → 人员 → 删除项。删除时若 ID 不存在会跳过（不报错）。

## 14. 完整调用示例

```bash
BASE=http://localhost:3000
```

## 15. 错误处理建议

1. 先调 `GET /external/health` 确认密钥与网络
2. 对 `409` 做幂等：创建前自带稳定 `id`，或捕获冲突后改走 `PATCH`
3. 批量写入用稳定业务 ID（写入 `id` + `externalMeta.bizId`），便于对账与重试
4. 删除操作默认级联，生产环境建议先查询确认再删
5. 人员字段尽量传系统已有姓名或钉钉 userid，避免产生无法匹配的游离名字
