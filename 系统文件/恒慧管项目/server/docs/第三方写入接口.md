# 恒慧管 · 第三方写入接口文档

第三方系统通过 **API Key** 调用本接口，向恒慧管写入项目、任务、评论、依赖、人员等数据，无需用户 JWT 登录。

配套只读查询见：[workbuddy.md](./workbuddy.md)

---

## 1. 前置条件

1. 在 `server/.env` 配置 `API_KEY`（可用 `npm run rotate-secrets` 生成）
2. 配置 `PUBLIC_BASE_URL` 为第三方可访问地址
3. 重启后端服务

未配置 `API_KEY` 时，全部写入接口返回 `503`。

---

## 2. 基础约定

### 2.1 Base URL

```
{PUBLIC_BASE_URL}/api
```

本地默认：`http://localhost:3000/api`

### 2.2 鉴权

| 方式 | 说明 |
|------|------|
| Header `X-Api-Key: <密钥>` | **推荐** |
| Query `?key=<密钥>` | 备选 |

密钥匹配环境变量 `API_KEY`。

### 2.3 统一响应

成功：

```json
{
  "code": 200,
  "message": "ok",
  "data": { }
}
```

失败：

```json
{
  "code": 400,
  "message": "错误原因",
  "data": null
}
```

| HTTP / code | 含义 |
|-------------|------|
| 200 | 成功 |
| 400 | 参数错误 |
| 401 | 密钥错误或缺失 |
| 404 | 资源不存在 |
| 409 | 冲突（如 ID 已存在、依赖重复） |
| 500 | 服务端写入失败 |
| 503 | 未配置 `API_KEY` |

### 2.4 Content-Type

请求体使用 JSON：

```
Content-Type: application/json
```

### 2.5 人员字段解析

凡涉及人员的字段（`manager` / `assignee` / `creator` / `author` / `teamMembers` 等）支持：

- 姓名（如 `王元斌`）
- 系统用户 `id`
- 钉钉 `userid` / `dingTalkUserId`
- 对象：`{ "name": "王元斌" }` 或 `{ "dingTalkUserId": "669701617" }`

服务端会尽量解析为系统内姓名；解析不到则原样写入字符串。

### 2.6 日期格式

日期字段接受：

- `YYYY-MM-DD`（推荐）
- `YYYY/M/D`
- 可被 `Date.parse` 解析的字符串

统一规范为 `YYYY-MM-DD`。

### 2.7 实时同步

写入成功后会广播 SSE 变更事件，已打开恒慧管前端的客户端会 soft-pull 刷新。

## 5. 项目

### 5.1 创建项目

```http
POST /api/external/projects
X-Api-Key: <密钥>
Content-Type: application/json
```

#### 请求体

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `name` | string | ✅ | 项目名称（亦接受 `title`） |
| `id` | string | | 自定义 ID；不传则自动生成 `PRJ-...` |
| `desc` | string | | 描述（亦接受 `description`） |
| `dept` | string | | 归属部门 |
| `manager` | string/object | | 项目负责人，默认取 creator 或「外部系统」 |
| `teamMembers` | string[] | | 团队成员（自动排除负责人） |
| `status` | string | | `active` / `paused` / `done` / `archived`，默认 `active` |
| `startDate` | string | | 开始日期，默认今天 |
| `endDate` | string | | 结束日期 |
| `archived` | boolean | | 是否归档 |
| `creator` | string | | 创建人 |
| `withTemplate` | boolean | | 是否生成标准阶段里程碑+门禁，**默认 true** |
| `documents` | array | | 项目文档列表 |
| `externalMeta` | object | | 第三方自定义元数据（原样保存） |

#### 响应 `data`

```json
{
  "project": { "id": "PRJ-...", "name": "...", "...": "..." },
  "templateTaskCount": 13
}
```

`withTemplate: true`（默认）时会自动创建 6 个阶段里程碑及 M1~M7 门禁任务。

#### 示例

```bash
curl -X POST "$BASE/api/external/projects" \
  -H "X-Api-Key: $KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "NCC 升级项目",
    "manager": "王元斌",
    "dept": "信息中心",
    "withTemplate": true,
    "externalMeta": { "source": "erp", "bizId": "PRJ-10086" }
  }'
```

不生成模板：

```json
{ "name": "轻量项目", "manager": "王元斌", "withTemplate": false }
```

---

### 5.2 更新项目

```http
PATCH /api/external/projects/:id
```

传入需修改的字段即可（部分更新）。支持字段同创建，另可传 `operator`（操作人，用于审计事件）。

响应：`{ "project": { ... } }`

---

### 5.3 删除项目

```http
DELETE /api/external/projects/:id?cascade=true
```

| 参数 | 说明 |
|------|------|
| `cascade` query | 默认 `true`：同时删除项目下全部任务及关联依赖；传 `false` 仅删项目 |

响应：

```json
{
  "project": { "...": "..." },
  "removedTaskIds": ["T-...", "T-..."]
}
```

## 6. 任务

### 6.1 枚举值

**状态 `status`**

| 值 | 含义 |
|----|------|
| `todo` | 未开始（默认） |
| `doing` | 进行中 |
| `paused` | 已暂停 |
| `done` | 已完成 |
| `abolished` | 已废止 |
| `archived` | 已归档 |

**优先级 `priority`**

| 值 | 含义 |
|----|------|
| `urgent` | 紧急（亦接受「紧急」） |
| `important` | 重要（亦接受「重要」） |
| `normal` | 普通（默认） |

**类型 `type`**

| 值 | 含义 |
|----|------|
| `temp` | 临时事项（无 `projectId` 时默认） |
| `normal` | 普通项目任务（有 `projectId` 时默认） |

---

### 6.2 创建任务

```http
POST /api/external/tasks
```

#### 请求体

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `title` | string | ✅ | 标题（亦接受 `name`） |
| `id` | string | | 自定义 ID；不传则 `T-...` |
| `desc` | string | | 说明 |
| `projectId` | string | | 所属项目；空则为临时事项 |
| `parentId` | string/null | | 父任务 / 所属里程碑 |
| `isMilestone` | boolean | | 是否阶段里程碑，默认 `false` |
| `type` | string | | `temp` / `normal` |
| `assignee` | string | | 负责人 |
| `creator` | string | | 创建人 |
| `status` | string | | 见枚举，默认 `todo` |
| `priority` | string | | 见枚举，默认 `normal` |
| `progress` | number | | 0~100 |
| `dueDate` | string | | 截止日期 |
| `planStartDate` | string | | 计划开始 |
| `actualStartDate` | string | | 实际开始 |
| `actualEndDate` | string | | 实际结束 |
| `estimatedHours` | number | | 预估工时 |
| `actualHours` | number | | 实际工时 |
| `informCollaborators` | string[] | | 告知协办 |
| `assistCollaborators` | string[] | | 协助协办 |
| `collaboratorEntries` | object[] | | `[{ "name":"...", "role":"inform\|assist" }]` |
| `attachments` | array | | 附件元数据 |
| `externalMeta` | object | | 第三方元数据 |
| `intakeMeta` | object | | 进件来源元数据 |

响应：`{ "task": { ... } }`

#### 示例：临时事项

```bash
curl -X POST "$BASE/api/external/tasks" \
  -H "X-Api-Key: $KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "title": "处理 NCC 报错工单",
    "assignee": "王元斌",
    "dueDate": "2026-08-30",
    "priority": "urgent",
    "desc": "来自运维系统"
  }'
```

#### 示例：项目下任务

```json
{
  "title": "完成需求确认",
  "projectId": "PRJ-XXXX",
  "parentId": "T-里程碑ID",
  "assignee": "王元斌",
  "dueDate": "2026-09-15",
  "status": "todo"
}
```

#### 示例：里程碑

```json
{
  "title": "01-启动过程组",
  "projectId": "PRJ-XXXX",
  "isMilestone": true,
  "assignee": "王元斌"
}
```

### 6.3 更新任务


```http

```

| 参数 | 说明 |
|------|------|

响应：

```json
{
  "task": { "...": "..." },
  "removedTaskIds": ["T-1", "T-2"],
  "removedCount": 2
}
```

## 8. 任务依赖

依赖语义：前置任务（predecessor）完成后，后置任务（successor）才可开始（Finish-to-Start）。

### 8.1 创建依赖

```http
POST /api/external/dependencies
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `predecessorTaskId` | string | ✅ | 前置任务（亦接受 `fromTaskId`） |
| `successorTaskId` | string | ✅ | 后置任务（亦接受 `toTaskId`） |
| `blockMode` | string | | `hard` 强阻塞（默认）/ `soft` 弱阻塞 |
| `note` | string | | 备注 |
| `type` | string | | 默认 `finish_to_start` |
| `id` | string | | 自定义 ID |
| `createdBy` | string | | 创建人 |

自动校验：任务存在、禁止自环、禁止成环、禁止重复。

响应：`{ "dependency": { ... } }`

### 8.2 更新依赖

```http
PATCH /api/external/dependencies/:id
```

可改：`note` / `blockMode` / `status`（`active` | `inactive`）

### 8.3 删除依赖

```http
DELETE /api/external/dependencies/:id
```

## 9. 人员

### 9.1 创建 / 更新人员

```http
POST /api/external/users
```

按 `id` → `dingTalkUserId` → `name` 依次匹配已有人员；匹配到则更新，否则新建。

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `name` | string | ✅ | 姓名 |
| `id` | string | | 系统用户 ID |
| `dingTalkUserId` | string | | 钉钉 userid（亦接受 `userid`） |
| `role` | string | | 如 `gm` / `admin` / `manager` / `member`，默认 `member` |
| `dept` | string | | 部门 |
| `position` | string | | 职位 |
| `active` | boolean | | 是否启用，默认 true |
| `profileKind` | string | | `staff`（默认）/ `contact` 等 |

响应：`{ "user": { ... }, "created": true|false }`

## 10. 工作日历

### 10.1 覆盖写入

```http
PUT /api/external/work-calendar
```

请求体可为完整日历对象，或 `{ "workCalendar": { ... } }`。

常用字段：

| 字段 | 说明 |
|------|------|
| `scheduleMode` | `alternate` 大小周 / `single` 全年单休 / `double` 全年双休 |
| `referenceDate` | 大小周基准周一 |
| `referenceIsSingleWeek` | 基准周是否单休 |
| `hoursPerDay` | 日工时 |
| `workStartHour` | 上班时刻（8.5 = 08:30） |
| `workEndHour` | 下班时刻 |
| `holidays` | 法定节假日数组 |
| `extraWorkdays` | 调休补班日数组 |

示例：

```json
{
  "scheduleMode": "alternate",
  "referenceDate": "2026-01-05",
  "referenceIsSingleWeek": true,
  "hoursPerDay": 8.5,
  "workStartHour": 8.5,
  "workEndHour": 17,
  "holidays": ["2026-01-01"],
  "extraWorkdays": ["2026-02-14"]
}
```

更完整说明见：[工作日历配置.md](./工作日历配置.md)

## 12. 批量写入

```http
POST /api/external/batch
```

一次完成多实体 upsert 与显式删除。有 `id` 且已存在则更新，否则创建。

#### 请求体

```json
{
  "withTemplate": false,
  "projects": [
    { "id": "PRJ-EXT-1", "name": "批量项目", "manager": "王元斌" }
  ],
  "tasks": [
    { "id": "T-EXT-1", "title": "任务A", "projectId": "PRJ-EXT-1", "assignee": "王元斌" },
    { "id": "T-EXT-2", "title": "任务B", "projectId": "PRJ-EXT-1", "assignee": "王元斌" }
  ],
  "taskDependencies": [
    { "predecessorTaskId": "T-EXT-1", "successorTaskId": "T-EXT-2" }
  ],
  "users": [
    { "name": "外部同步员", "dingTalkUserId": "123456", "dept": "信息中心" }
  ],
  "removedProjectIds": [],
  "removedTaskIds": [],
  "removedDependencyIds": []
}
```

| 字段 | 说明 |
|------|------|
| `withTemplate` | 仅对**新建**项目生效；默认 false（批量场景避免刷大量模板任务） |
| `projects` | 项目 upsert 列表 |
| `tasks` | 任务 upsert 列表 |
| `taskDependencies` | 依赖 upsert 列表 |
| `users` | 人员 upsert 列表 |
| `removedProjectIds` | 显式删除项目（级联任务） |
| `removedTaskIds` | 显式删除任务 |
| `removedDependencyIds` | 显式删除依赖 |

#### 响应 `data`

```json
{
  "projectsUpserted": 1,
  "tasksUpserted": 2,
  "dependenciesUpserted": 1,
  "usersUpserted": 1,
  "projectsRemoved": 0,
  "tasksRemoved": 0,
  "dependenciesRemoved": 0
}
```

处理顺序：项目 → 任务 → 依赖 → 人员 → 删除项。删除时若 ID 不存在会跳过（不报错）。

## 13. 完整调用示例

```bash
BASE=http://localhost:3000
KEY=你的API_KEY

# 1) 健康检查
curl -s "$BASE/api/external/health" -H "X-Api-Key: $KEY"

# 2) 创建项目（不带模板）
PROJ=$(curl -s -X POST "$BASE/api/external/projects" \
  -H "X-Api-Key: $KEY" -H "Content-Type: application/json" \
  -d '{"name":"对接演示项目","manager":"王元斌","withTemplate":false}')
echo "$PROJ"

# 3) 创建任务
curl -s -X POST "$BASE/api/external/tasks" \
  -H "X-Api-Key: $KEY" -H "Content-Type: application/json" \
  -d '{"title":"完成接口联调","assignee":"王元斌","dueDate":"2026-08-30","priority":"important"}'

# 4) 更新进度
curl -s -X PATCH "$BASE/api/external/tasks/T-XXXX" \
  -H "X-Api-Key: $KEY" -H "Content-Type: application/json" \
  -d '{"status":"doing","progress":50}'

# 5) 写评论
curl -s -X POST "$BASE/api/external/tasks/T-XXXX/comments" \
  -H "X-Api-Key: $KEY" -H "Content-Type: application/json" \
  -d '{"content":"第三方系统已同步","author":"外部系统"}'
```

PowerShell 示例：

```powershell
$BASE = "http://localhost:3000"
$KEY = "你的API_KEY"
$h = @{ "X-Api-Key" = $KEY; "Content-Type" = "application/json" }

Invoke-RestMethod -Method Post -Uri "$BASE/api/external/tasks" -Headers $h -Body (@{
  title = "PowerShell 写入测试"
  assignee = "王元斌"
  dueDate = "2026-08-30"
} | ConvertTo-Json)
```

## 14. 错误处理建议

1. 先调 `GET /external/health` 确认密钥与网络
2. 对 `409` 做幂等：创建前自带稳定 `id`，或捕获冲突后改走 `PATCH`
3. 批量写入用稳定业务 ID（写入 `id` + `externalMeta.bizId`），便于对账与重试
4. 删除操作默认级联，生产环境建议先查询确认再删
5. 人员字段尽量传系统已有姓名或钉钉 userid，避免产生无法匹配的游离名字
