# 恒慧管 UI 升级（前端工程化 · 小 B 路线）· 需求文档（草稿）

> 状态：正式 v1.0 · 小 B 已落地脚手架（Phase 0–5）· 生产切换待验收
> 日期：2026-09-10
> 关联文档：`草稿-恒慧管改造需求v1_20260910.md`（功能/交互层，已落地，本方案与之独立）

---

## 一、背景（已代码校验）

恒慧管是完整系统：前端页面 + 后端 server（Node/Express）+ MySQL 数据库。

- **钉钉里的 H5 应用**：目前是一整个约 1MB 的单文件网页（`恒慧管.html`，原生 JS、内联样式、无构建工具），由后端以静态文件方式发出、在钉钉里打开。
- **另有独立钉钉小程序**（`server/miniapp/`，仅做任务概览），与 H5 并存、互不影响。
- 现状**没有前端工程化**（后端无前端构建脚本、无前端框架依赖）。
- v1 功能/交互改造已落地，本方案是**独立的 UI / 前端工程化升级**，可单独排期、单独验收。

---

## 二、目标

1. 把单文件网页重构成工程化前端，解决「1MB 大杂烩、难维护、易改崩」的底层问题。
2. 提升钉钉 H5 使用体验：打开更快、手机不卡、支持夜间模式、界面更统一。
3. 过程中**不破坏现有功能、不动数据安全**。

---

## 三、方案选型结论

**采用小 B 路线**：用构建工具把单文件按原生 JS 拆分成多模块，不引入前端框架。

> 大 B（引入 vue/react 整体重写）已排除——工期 1–2 个月起、回归风险高，且当前没有必须用框架的复杂交互需求。小 B 先打牢地基与体验，后续若确有需要再渐进迁移。

---

## 四、需求清单

### P0｜感知强 · 风险低 · 优先做

- **R1 视觉样式统一**
  把散落在各处的硬编码颜色、多套按钮/标签样式，收拢成统一规范。结果：界面更一致，以后改主题色一处生效、不用满文件找。
- **R2 夜间模式**
  支持深色界面（内部工具常盯屏，夜间不刺眼）。偏好记忆本期可先用「浏览器本地记忆」实现，后续可升级为「按账号持久化」（见待确认项）。
- **R3 移动端 / 平板适配体系化**
  手机钉钉、平板上布局统一规整，从「能用但别扭」提升到「好用」。

### P1｜体验提升

- **R4 首屏加载优化**
  打开更快、手机不卡（工程化拆分带来的直接收益，作为需求提出，具体手段由开发评估）。
- **R5 交互反馈补齐**
  空状态提示、加载态、操作成功/失败提示等微交互，减少「点了没反应」的困惑。
- **R6 资源稳定**
  图标等静态资源不再依赖公网，内网 / 弱网下也能正常显示。

### P2｜可选增值

- **R7 数据看板可视化**
  项目进度、里程碑、卡点聚合成图表（有数据库支撑，天然可做）。本期可选，不阻塞主线路。

## 五、对钉钉 / 服务器的配置影响（重点）

一句话：**主要工作量在「前端重做 + 服务器发文件方式调整」，基本不碰钉钉后台，不碰数据和业务逻辑。**

### 钉钉后台：不用动
- 只要做的时候**保持入口地址与域名不变**（仍是现在的 `/app` 地址），钉钉开放平台**零配置、无需找管理员重新发布**。
- 应用类型、CorpId、AppKey、HTTPS 安全域名全部不用改。
- 唯一例外：若实施时把入口路径改了（如 `/app` 改别处），才需改钉钉应用的「主页地址」→ 列为硬约束，禁止改路径。

### 服务器后端：改一处发文件方式 + 发布多一步
- **改一处**：现在后端是「把那个 1MB 大文件直接发给浏览器」，改造后改为「把构建好的整套前端包发出来」。这是最主要的一处改动。
- **发布多一步**：原来覆盖个 HTML 文件就完事；改造后要先「构建」再发布，加进发布流程即可。
- **不用动的**：MySQL 数据库、后端接口、钉钉免登逻辑。

### 新增：一套前端工程
- 新建前端项目（拆分模块 + 构建工具），不碰现有可用功能。
- 钉钉原生小程序（miniapp）不受影响，本方案只动 H5 页面。

## 六、范围边界

**做（范围内）**
- 前端展示层工程化拆分、构建部署
- 设计样式统一（R1）
- 夜间模式（R2）
- 响应式体系化（R3）
- 首屏性能优化（R4）
- 交互反馈补齐（R5）
- 静态资源自托管（R6）

**不做（边界外）**
- 不改数据库结构
- 不改后端接口业务逻辑
- 不重写钉钉小程序（miniapp）
- 不回炉 v1 已落地的功能

---

## 七、硬约束（必守）

1. **钉钉 H5 入口路径与域名保持不变**，否则触发钉钉后台变更（协调成本）。
2. **保留防白屏的安全设置**（钉钉 web-view 白屏防护），不能删。
3. **前端调用接口保持同源**，避免引入跨域问题。
4. 改造期间**保留旧单文件网页可回滚**，出问题能一键还原。

---

## 八、验收标准

- [ ] 手机钉钉实打开恒慧管 H5 **不白屏**、现有功能全部可用
- [ ] 首屏加载时间较现状（1MB 全量）**明显下降**
- [ ] 夜间模式可用（本期至少浏览器本地记忆生效）
- [ ] 现有功能**零回归**（对照测试通过）
- [ ] 入口地址 / 域名与改造前一致，钉钉后台未做任何改动

---

## 九、风险与应对

| 风险 | 应对 |

| 误改钉钉入口导致要动后台 | 硬约束 1 锁死入口路径与域名 |
